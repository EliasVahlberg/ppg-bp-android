# App icon assets (issue #8)

`icon-android-adaptive-foreground.svg` is derived from `icon-android.svg`
(the `android` variant of `docs/branding/generate_logo.py`'s `render_icon_svg`,
kept in this same directory), re-centered and scaled to fit Android's
adaptive-icon safe zone instead of the flat icon's own 240x240 canvas.

It is **not** currently produced by `generate_logo.py` itself -- it was
derived by a one-off script using the same `build_icon_group()` /
`_phone_glyph()` helpers plus the bounding-box constants already used
by `render_banner_svg()` (halo_pad=10, x=[14-10, 226+10], y=[PEN_TOP-10,
PEN_BOTTOM+10]), scaled so the content's longer dimension fills 62% of
a 108-unit adaptive-icon canvas, centered.

If this repo's icon changes (waveform retuned, colors changed, glyph
changed), this file needs to be regenerated by hand using that same
approach, or -- better -- by adding a `--kind adaptive-foreground`
option to `generate_logo.py` in the `ppg-bp` repo (the actual source of
truth for all three repos' branding) so it's reproducible from a single
command instead of re-deriving the safe-zone math again. Not done as
part of closing #8 since it's a change to a different repo's tooling,
out of scope for this issue -- flagged here as a known follow-up.

## Regenerating the flat launcher icons (mipmap-*)

The flat icon (`app/src/main/res/mipmap-*/ic_launcher.png`,
`ic_launcher_round.png`) is `icon-android.svg` rasterized directly at
each density (48/72/96/144/192px), via headless Chrome:

```bash
python3 docs/branding/generate_logo.py --kind icon --variant android \
    --out-dir /tmp/icon_gen --no-preview
# then wrap in a sized HTML shell and screenshot at each density --
# window-size alone does NOT scale an SVG's intrinsic viewBox, the
# HTML/CSS must set explicit width/height matching the target size.
```
